## 제품 콘셉트

> **마신 와인의 취향과 실제 구매가를 쌓아, 다시 살 와인과 다시 살 가격을 기억하는 앱.**

현재 제품: 구매 여부와 독립적인 와인·시음 기록에 여러 구매·병을 연결하고, 사용자가 입력한 참고 가격으로 구매 단가를 비교하는 개인 와인 기록 앱.

다음 제품 방향: 와인 한 종류에 관심·구매·보유·시음 이력을 연결하고, 다음 선택에 필요한 개인 기록을 다시 꺼내 보는 경험.

### 우선 사용자와 사용 목적

초기 사용자 가설: 한국어·원화 중심으로 와인을 구매하거나 시음하며, 자신의 취향과 구매 경험을 기억하고 싶은 개인 사용자. 실제 사용성 검증이 필요한 가설.

| 사용 순간 | 앱이 도와야 할 일 |
|---|---|
| 와인바·식당·시음회에서 마신 직후 | 구매 정보 없이 사진·이름과 짧은 감상 저장 |
| 매장에서 관심 있는 와인을 발견했을 때 | 관심 목록, 본 가격, 과거 구매가·내 평가 확인 |
| 같은 와인을 다시 구매했을 때 | 기존 와인 아래 새 구매와 병 추가 |
| 집에서 한 병을 마셨을 때 | 남은 병수 갱신과 선택적인 시음 기록 연결 |
| 다시 구매할지 고민할 때 | 내 평점·감상·재구매 의사·이전 구매가 함께 확인 |
| 기록을 옮기거나 복구할 때 | 와인·구매·노트·사진을 함께 내보내고 복원 |

목표 사용자 흐름:

```text
관심 와인 또는 구매 없는 시음으로 시작
    → 필요할 때 구매·병 추가
    → 보유·소비 상태와 시음 기록 연결
    → 취향·구매가·참고 가격 확인
    → 재구매 판단
```

관심 여부·보유 여부·시음 이력은 서로 겹칠 수 있는 속성. 한 번에 하나만 선택하는 배타적 상태로 고정하지 않는 방향.

### 유지할 제품 원칙

- **로컬 우선:** 계정이나 외부 데이터 서비스 연결 없이 개인 기록 사용 가능.
- **기록 소유권:** 사진을 포함한 내보내기·복원과 데이터 보존을 제품의 핵심 범위로 취급.
- **적은 입력:** 모르는 정보 때문에 첫 기록을 막지 않고, 상세 정보는 나중에 보완.
- **다음 선택에 도움:** 개인의 취향 평가와 가격 비교를 각각 보존하고 함께 조회.
- **근거 있는 가격 표시:** 출처·시점·비교 조건·표본 수를 드러내고 부족한 근거를 표시.
- **선택적인 외부 연동:** API 접근, 이용 조건, 매칭·데이터 품질 확인 후 별도 어댑터로 추가.

### 제품 가설의 검증 목표

- 이름 또는 사진 중심의 첫 기록 저장까지 **30초 이내**를 사용성 목표로 설정. 현재 측정 결과는 없음.
- 구매하지 않은 와인도 가짜 구매일·구매가 없이 기록 가능.
- 동일 와인의 재구매·여러 병·여러 시음 기록을 한 상세 화면에서 확인 가능.
- 가격 비교 화면에서 비교 대상과 기준 시점, 참고 가격 수를 사용자가 확인 가능.
- 내보낸 기록과 사진을 복원한 뒤 개수와 연결 관계가 원본과 일치.

기능 참고: [CellarTracker 공식 앱 소개](https://mobileapp.cellartracker.com/)의 병·구매·시음 기록 관리, [Vivino 공식 앱 소개](https://www.vivino.com/en/app)의 스캔·평가·셀러·관심 목록. 확인일: 2026-11-02. Miruvor의 차별화와 반복 사용 이유는 위 사용자 흐름을 통해 검증할 대상.

## 현재 진행 상황

현재 평가: **와인·구매·병을 분리하고 보존 정책을 구현한 초기 MVP.**

2026-11-10 진행 갱신: P0 설계와 P1 구현 완료. 최소 등록·검색 상세 진입·병 상태 입력도 연결했으며, P2·P3의 전체 사용자 흐름은 후속 범위. API 입력 보조는 제안 단계 유지.

2026-11-26 진행 갱신: 기존 Cellar 탭을 현재 보유 와인 중심의 `내 셀러`로 변경. 전체 기록은 별도 화면으로 유지. 보관 위치·구매 여부 필터, 현재 병들의 구매 원가 집계, 병별 상태·위치 관리와 구매·선물 추가 흐름 구현. P2·P3 전체 완료와는 구분.

판정 기준: 저장소 코드·문서와 아래 자동 검사·Android 릴리스 APK 검증 결과. 실제 기기 실행·업그레이드, 스토어·iOS 배포 및 사용성 목표 달성은 별도 검증 대상.

- 스키마 변환 후 중간 실패를 주입하여 스키마·행·DB 버전이 v1으로 복귀하고 사진이 남는 것을 확인.
- 음수 기존 금액·범위 밖 세부 평가·다른 와인에 연결된 노트·깨진 외래 키는 값을 추측하거나 버리지 않고 이전 중단.
- 구매·병·노트 독립 삭제, 전체 삭제 영향 재확인, 공유 사진 보존, 파일 정리 실패 후 재시도와 재시작 후 큐 유지.
- 잘못된 사진 교체 저장 실패 시 원래 사진·DB 참조 유지, 새로 가져온 복사본만 정리.
- 구매 없는 시음, 같은 와인 여러 병·재구매, 선물과 상태 정정, 신규 소비 체크, 가격 이력 독립 편집의 화면 흐름.

### P1 — 와인과 구매 분리

상태: **구현·자동 검증 완료, 2026-11-10**. DB v2와 화면·저장소에 반영; 실기기 검증은 P5에서 별도 수행.

범위:

- P0 필드 계약에 따른 Purchase 테이블 도입, Bottle의 선택 purchaseId 및 미상 값·상태 필드 반영.
- 와인을 먼저 등록하고, 선택적으로 구매·병을 추가하는 경로.
- 기존 와인을 골라 재구매와 여러 병을 등록하는 경로.
- 구매나 특정 병 없이 와인에 시음 기록을 연결하는 경로.
- P0에서 정한 삭제·보존, 사진 참조, 같은 와인·용량·수량의 연결 제약 반영.
- DB 스키마 변경 시 v1 데이터 이전, 스냅샷 및 실제 데이터 보존 테스트 추가.

완료 조건:

- 구매 없는 와인과 시음 기록 저장 시 가짜 구매 행이 생기지 않음.
- 같은 와인을 세 병 구매하면 Wine 한 건, Purchase 한 건(quantity=3), Bottle 세 건으로 연결.
- 다른 날짜의 재구매 이력과 시음 기록을 같은 와인에서 조회 가능.
- 구매 한 건의 삭제가 다른 병이나 보존 대상 시음 기록·사진을 제거하지 않음.
- 병 삭제 시 시음 노트는 와인에 남고 병 연결만 해제; 전체 영구 삭제와 일반 삭제의 영향 구분.
- 기존 v1 와인·구매·가격·노트·사진 경로의 보존과 외래 키 무결성 검증 통과.
- [P0 예시](domain-policy.md#examples)의 저장·삭제·연결 오류·이전 실패 사례 검증. 상태 입력은 이번 최소 UI에 포함; 소비·시음 결합 화면과 실기기 검증은 별도.

완료 근거: [정책 테스트](../test/database/domain_policy_test.dart), [실제 파일 DB 이전·롤백 테스트](../test/drift/app_database/preservation_test.dart), [사진 수명 테스트](../test/miruvor_store_image_lifecycle_test.dart), [위젯 테스트](../test/widget_test.dart). 생성 스키마 비교와 정적 분석을 포함한 전체 42개 검사 통과.

### P2 — 빠른 기록과 화면 정리

상태: **기반 일부 구현**. 이름 또는 사진 등록·관심 상태·상세 진입·홈 의미 정리는 P1에서 반영. 재구매 의사·세부 맛 입력, 메뉴·검색 통합, 첫 기록 시간 측정은 남은 범위.

2026-11-26 추가 완료: **내 셀러**는 집에 보유한 실제 병 목록, **전체 와인 기록**은 구매 없는 시음·관심·과거 기록을 포함한 목록으로 분리. 같은 Wine ID의 보유 병만 묶고, 소비·선물·반품 병은 제외. 구매 이력을 삭제한 병도 보유 상태라면 유지하며 금액만 미상 처리.

범위:

- 이름 또는 사진 중심의 빠른 저장과 상세 정보 나중 보완. 사진만 저장한 기록의 미확인 정보 표현 포함.
- 구매 기록과 시음 기록의 진입 목적 구분; 한 줄 감상과 재구매 의사 도입.
- 관심 와인 저장 및 이후 구매 연결.
- 내 와인 검색 통합과 결과 → 상세 → 기록 추가 동선 연결.
- 홈의 집계 이름·정렬 의미 정리, 메뉴 언어 정리.

후속 화면안: `홈 / 내 셀러 / 내 와인 / 시음 기록`. 보유 관리의 독립 진입 유지. 현재는 5개 탭 중 Cellar를 내 셀러로 바꾸고 전체 기록은 셀러 안에서 별도 진입; Search·Prices 통합은 후속. 검색은 내 와인에 통합하고 가격·구매·시음 이력은 상세에서 함께 조회하는 방향.

완료 조건:

- 생산자·국가·가격을 몰라도 최소 기록을 저장하고 나중에 보완 가능.
- 실제 사용자 흐름에서 첫 기록 저장 시간을 측정하고 30초 목표 충족 여부 기록.
- 검색 결과에서 해당 와인 상세로 이동 가능; G-04·G-06 해결.
- 관심 와인의 구매 전환 시 기존 와인·참고 가격·노트 연결 유지.
- 상세 화면에서 감상과 재구매 의사를 다시 확인 가능.

### P3 — 보유·소비·시음 연결

상태: **기반 일부 구현**. 병 상태 편집·재고 계산·G-03 수정과 저장소의 시음/소비 원자적 저장은 P1에서 검증. 새 노트의 병 선택, 소비하며 시음을 쓰거나 건너뛰는 화면은 남은 범위.

2026-11-26 추가 완료: 셀러 카드에서 각 병의 구매 정보 확인, 위치·정보 수정, 소비·선물·반품 처리. 상태 변경은 확인 후 해당 병만 갱신하고 기록은 보존. 사건 날짜를 추측하지 않고 미상 유지; 날짜를 아는 경우 병 정보에서 입력.

범위:

- 병 단위 보유·소비·선물·반품 상태와 남은 병수 갱신.
- 소비 처리 시 시음 기록을 함께 남기거나 건너뛰는 선택 흐름.
- 구매 없이 시음만 했거나 여러 차례 같은 병을 시음한 경우의 처리.
- 신규 등록의 소비 체크 전달 누락 G-03 수정.

초기 범위: P0에서 정한 inStock·consumed·gifted·returned의 입력 흐름과 시음 연결. 개봉·남은 액량·상태 변경 전체 타임라인은 후속 범위.

완료 조건:

- 세 병 중 한 병 소비 시 남은 병수는 두 병, 구매·시음 이력은 유지.
- 신규 등록·수정의 소비 상태가 모두 저장되고 다시 조회해도 일치.
- 단순 시음 기록 저장만으로 보유 병수가 의도치 않게 감소하지 않음.
- 병 소비 처리와 구매 없는 시음 기록이 각각 독립적으로 사용 가능.
- 선물·반품 처리 시 병 기록과 구매·시음 이력은 유지, 재고만 감소. 상태 정정·복귀와 중복 요청에도 재고 일치.

### P4 — 가격 판단의 근거 표시

범위:

- 표현 기준을 사용자가 기록한 참고 가격으로 명확화.
- 출처·관측 시점·표본 수·최저/평균/최고 및 구매가 차이 표시.
- 빈티지·용량·통화·배송비·할인 조건 등 비교 가능 조건의 최소 범위 결정.
- 관측일 입력, 재고·오래된 자료·동일 출처 중복 관측치의 포함 기준 결정.
- 표본 부족·비교 조건 불일치 시 가격 차이 표시와 최종 판정을 구분.
- 개인의 취향·재구매 의사와 참고 가격 대비 유불리를 별도로 표시.

완료 조건:

- 사용자가 비교에 포함된 가격과 제외 이유를 확인 가능.
- 관측치 0개·1개·여러 개, 오래된 자료, 조건이 다른 자료에 대한 표시 정책과 검증 사례 마련.
- 유효하지 않은 금액 입력 처리와 평균이 0인 경우의 동작 명시·검증.
- 시장 전체의 확정적인 적정가로 오해할 표현 정리; G-05 해결.
- 외부 API 없이 수동 참고 가격과 과거 구매가로 사용 가능.

### P5 — 백업·복원과 사용 검증

상태: 사용자용 백업·복원과 기기 사용 검증은 미착수. Android APK 빌드·서명 검증과 직접 다운로드 사전 릴리스만 먼저 완료한 범위.

범위:

- 와인·구매·병·가격·시음 기록과 사진을 함께 내보내기.
- 백업 형식 버전, 파일 검증, 사진의 기기별 절대 경로 의존 제거.
- 복원 시 ID·참조 관계·사진 연결 보존, 실패 시 기존 데이터 보존.
- 기존 데이터가 있는 저장소의 병합·덮어쓰기 정책 결정. 초기 권장 범위는 빈 저장소 복원부터이며, 구현 전 명시 필요.
- 실제 기기에서 대표 시나리오, 재시작 후 영속성, 사진 선택·권한 확인.

완료 조건:

- 내보내기 → 빈 저장소 복원 후 레코드 수·필드·연결 관계·사진 내용 일치.
- 누락되거나 손상된 백업을 감지하고 기존 기록을 훼손하지 않는 실패 처리 검증.
- 원래 기기 경로가 없는 복원 환경에서도 사진 조회 가능.
- 지원 대상으로 정한 기기에서 아래 대표 시나리오와 재시작 후 상태 유지 검증.
- 플랫폼별 검증 결과·미검증 항목 기록. 배포를 진행할 경우 앱 식별자·release 서명·빌드 검증 별도 완료.

## 다음 마일스톤의 대표 완료 시나리오

아래는 P2~P5까지 이어지는 전체 사용 경험의 검증 목표. P1에서 개별 저장·삭제·상태 동작은 자동 검증했으며, 사용자 입력 시간·결합 화면·기기 실행·사진 포함 복원은 미검증.

1. 와인바에서 마신 와인을 구매 정보 없이 빠르게 기록.
2. 감상과 재구매 의사를 저장하고 나중에 조회.
3. 같은 와인을 매장에서 발견해 참고 가격 기록.
4. 해당 와인 세 병 구매 후 기존 와인에 연결.
5. 한 병 소비 시 두 병이 남고, 시음 기록을 선택적으로 연결.
6. 이전 구매가·참고 가격의 조건·내 감상을 함께 확인.
7. 앱 재시작 후 기록과 상태 유지.
8. 사진을 포함해 내보내고 다른 경로의 빈 저장소에 복원한 뒤 데이터 일치 확인.
